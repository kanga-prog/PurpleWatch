# PW-206 — End-to-end Sysmon telemetry validation

## Objective

Validate the complete PurpleWatch Cyber Lab telemetry path:

`Windows → Sysmon → Wazuh Agent → Wazuh Manager`

## Endpoint

- Windows endpoint: `PW-WIN11-01`
- Endpoint address: `192.168.56.106`
- Wazuh Manager: `192.168.56.105`
- Wazuh Agent ID: `001`

## Preconditions

Before the controlled test:

- `Sysmon64` was `RUNNING`
- `Sysmon64` startup type was `AUTO_START`
- `WazuhSvc` was `RUNNING`
- `WazuhSvc` startup type was `AUTO_START`
- Wazuh Manager reported agent `001 / PW-WIN11-01` as `Active`

## Controlled marker

A benign command was generated on the Windows endpoint:

`cmd.exe /c echo PW206-E2E-ARCHIVE-VALIDATION`

## Local Sysmon evidence

Sysmon recorded the controlled process as Event ID `1`.

Validated fields included:

- Provider: `Microsoft-Windows-Sysmon`
- Channel: `Microsoft-Windows-Sysmon/Operational`
- Event ID: `1`
- Image: `C:\Windows\System32\cmd.exe`
- Command line contained: `PW206-E2E-ARCHIVE-VALIDATION`

## Wazuh Manager evidence

The same marker was confirmed on the Wazuh Manager in:

`/var/ossec/logs/archives/archives.json`

Validated fields included:

- Agent ID: `001`
- Agent name: `PW-WIN11-01`
- Agent IP: `192.168.56.106`
- Manager: `wazuh-server`
- Decoder: `windows_eventchannel`
- Event channel: `Microsoft-Windows-Sysmon/Operational`
- Event ID: `1`
- Image: `C:\Windows\System32\cmd.exe`
- Command line contained: `PW206-E2E-ARCHIVE-VALIDATION`

Wazuh also evaluated the event with detection rules including:

- Rule `92052` — Windows command prompt started by an abnormal process
- Rule `92032` — Suspicious Windows cmd shell execution
- MITRE ATT&CK technique `T1059.003` — Windows Command Shell

## Temporary archive validation

The generic Sysmon Event ID 1 rule `61603` is level `0`, so normal process creation does not necessarily generate an alert.

For PW-206 validation only:

- `logall_json` was temporarily changed from `no` to `yes`
- the Wazuh Manager was restarted
- the marker was confirmed in `archives.json`
- `logall_json` was restored to `no`
- the Wazuh Manager was restarted again
- agent `001 / PW-WIN11-01` remained `Active`

Final settings:

- `logall = no`
- `logall_json = no`
- `wazuh-manager = active`

## Result

PW-206 successfully validated:

`Windows → Sysmon → Wazuh Agent → Wazuh Manager`

The end-to-end telemetry path is operational.

## Security

- No credentials were committed.
- No enrollment key was exposed.
- No `client.keys` content was stored.
- No raw event log was committed.
- Full JSON archiving was disabled immediately after validation.
- Both laboratory VMs were cleanly powered off after testing.
